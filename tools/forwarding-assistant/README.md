# 如如转运助手 v0.2.0 — 自动逐单查物流（测试版）

淘宝 / 天猫 / 拼多多 Chrome MV3 插件。本版新增「一键批量抓取」，目的是从已购订单中**逐单访问详情与物流**，不再要求用户手动打开每笔物流。**尚未验证真实淘宝/拼多多登录页的完整流程，请按测试版使用。**

## 安装

1. 下载 `ruru-forwarding-assistant-v0.2.0.zip` 后**解压**。
2. 打开 Chrome `chrome://extensions`，打开「开发者模式」→「加载已解压的扩展程序」。
3. 选择解压出来的文件夹，确保**此文件夹根目录直接有 `manifest.json`**。
4. 如果已经安装旧版，建议先备份：旧版「管理全部」→「导出 JSON」；然后在扩展页面点击「重新加载」或替换旧版文件夹。解压时不要把不同版本的文件混放。
5. Chrome 使用同一 Google 账号登录并开启同步时，可通过 `chrome.storage.sync` 在已安装此插件的电脑共享记录；仍有约 100KB 配额。

## 一键批量抓取（淘宝/天猫）

- 在淘宝已登录的 Chrome 里，打开插件，可停留在**购物车**或淘宝其他页面，点击 **「一键批量抓取」**。
- 插件将打开一个**非活动标签页**访问已买到的宝贝：`https://buyertrade.taobao.com/trade/itemlist/list_bought_items.htm`。
- 扫描可识别的订单卡片，保存订单与商品，逐单访问页面上可见的「查看物流」「订单详情」链接；只有有明确只读名称的按钮才会被自动点击。
- 查看物流详情并提取运单号。对多个商品/多个包裹，仅在上下文明确时自动匹配商品；否则保留运单并允许管理页手工指定。
- 默认最多尝试 40 单 / 5 页；仅在页面提供可解析的「下一页」链接时自动翻页。列表结构变化可能导致识别不到订单或按钮。
- 可关闭弹窗，回到插件查看进度与失败原因。点击「停止」会在当前订单处理后结束。
- 完成后复制运单号、标记已转运、搜索、备注、导出 CSV/JSON。

## 拼多多卡片级自动适配（v0.2.1）
根据实拍的拼多多页面设计：一个商品卡片附有「更多 / 申请退款 / 查看物流 / 确认收货」；列表未必显示订单号。
1. **先打开拼多多已登录的「我的订单」列表**，确认卡片可见「查看物流」。选择拼多多或保持平台「全部」，点击「一键批量抓取」。
2. 插件另开一个工作标签页，适度滚动加载商品，逐卡确认「查看物流」按钮及商品名，最多处理 40 个卡片。
3. **仅点击准确文字「查看物流」的控件**，绝不点击旁边的「确认收货」「退款」。
4. 优先从物流弹层提取；若出现独立详情页，在确认来源后读取。无法提取单号的卡片不保存假结果，记入失败提示。
5. 如果页面无真实订单号，但成功识别到运单号，插件会以 `PDD-PENDING-…` 创建临时引用，并在界面明确提示「订单号待核对」。CSV 中真实订单号留空，临时引用单列输出。
6. 卡片可能含多个商品；不明确的一对多关系不强行配对。没有可靠识别的页面需要提供物流详情截图继续完善。

自动化仅在用户主动点击时运行，并只访问当前账号可以查看的内容；不读取后台私有接口、不绕过验证码或平台风控。**尚未在用户真实页面上实测**，成功率需实测评估。

## 安全与限制

- 只使用浏览器**现有会话里能查看的页面内容**，不读取 Cookie、密码或调用私有接口，不绕过登录/验证码、反爬或平台风控。
- **只打开订单/物流详情**；绝不自动点击确认收货、付款、退款、删除订单等动作。
- 使用新开标签页逐个抓取，不直接操作用户所在的购物车。遇到登录/验证时打开工作标签页供用户处理。
- 自动识别依赖网页 DOM，实测前**不能保证**成功率。建议先用少量不含敏感信息的订单验证商品↔运单对应关系。
- 不同电脑同时修改相同订单可能出现最近写入覆盖，故定期导出 JSON 备份更稳妥。
- Chrome 同步存储不是淘宝/拼多多账号同步：两台电脑仍须安装插件、使用相同 Chrome 同步账号。注意 100 KB 等配额。
- 商品和运单属于私人数据，切勿向公开仓库提交已导出订单 JSON/CSV。

## 文件说明

`manifest.json`：权限和注入；`crawler.js`：仅只读可见数据的订单发现/页面点击；`background.js`：批量任务、逐单导航、进度和停止；`content.js`：普通当前页识别；`storage.js`：同订单合并与同步；`popup.html` / `dashboard.html` / `app.js` / `style.css`：界面、导入导出与标记。
